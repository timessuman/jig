# Jig Documentation Site — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build Jig's documentation website at `~/projects/jig-site`, generated from the published `jig-ui` tarball, fetched without being depended on, while recording every place a fresh agent drifts from Jig's rules.

**Architecture:** A static Astro site that fetches the published `jig-ui@0.7.1` tarball into a gitignored corpus directory and generates ~121 pages plus 119 plain-text endpoints from the package's own `rules/`, `tokens/` and `rules.index.json`. Content parsing is pure TypeScript, unit-tested, and cross-checked at build time against the CLI's own output so the site and the CLI can never disagree about which rules exist. Presentation is built by fresh subagents from Jig's rules alone.

**Tech Stack:** Astro 7.3.2, Tailwind 4.3.3 (`@tailwindcss/vite`), Pagefind 1.5.2, TypeScript, Vitest. The Jig corpus comes from `jig-ui@0.7.1`'s published tarball, fetched at build time — **not** a dependency.

**Spec:** `docs/superpowers/specs/2026-09-11-jig-site-design.md` (in the `squint` repo). Executors must read it — §2 explains why parts of this plan are deliberately silent.

## Global Constraints

- **Node ≥ 20.** Required by the `jig` CLI (`engines.node >= 20`).
- **Exact pins, no ranges:** `astro@7.3.2`, `tailwindcss@4.3.3`, `@tailwindcss/vite@4.3.3`, `pagefind@1.5.2`. The Jig corpus is pinned separately at `0.7.1`, in `scripts/fetch-corpus.mjs`, because it is not a dependency.
- **`jig-ui` MUST NOT appear in `package.json`.** Not in `dependencies`, not in
  `devDependencies`. Jig is a tool you install — a skill and a CLI — not a package
  a project depends on. This site is a user project like any other, and a user
  project that lists `jig-ui` models the wrong pattern for everyone who copies it.
  `grep jig-ui package.json` must return nothing.

- **The corpus is fetched, not depended on.** The site still needs `rules/*.md`,
  `rules.index.json` and `tokens/*.css` on disk to generate ~121 pages.
  `scripts/fetch-corpus.mjs` runs `npm pack jig-ui@0.7.1`, which downloads the
  published tarball and verifies its integrity **without installing it**, and
  extracts it to a gitignored `.jig-corpus/`. Version pinned in one constant;
  `prebuild` runs it so a clean checkout builds. 0.7.1 is the first version whose `02-tokens.md` states the token layer's real
  location, so nothing earlier should be pinned here.

  The two rejected alternatives, for the record: reading from
  `~/.claude/skills/jig/rules/` makes the build depend on one machine's home
  directory, and vendoring with `jig install --scope project` is refused outright
  while a global install exists (`install.ts:43-47`).

- **The corpus is content, not guidance.** Render its rules as page content. Never
  read them to decide how to build something — design guidance comes from `/jig`,
  every time. Never import anything from `.jig-corpus/` as a library.
- **Static output.** `output: 'static'`. No SSR adapter.
- **Fonts are self-hosted.** No Google Fonts link, no CDN. Use `@fontsource-variable/*` packages.
- **`src/fetch.ts` is a reserved filename in Astro 7.** Do not create it.
- **`jig check` must pass.** Exemptions live only in `jig.config.json`, and every exemption needs a matching `DRIFT.md` entry naming why that file cannot consume the cascade. No exemption may be added to silence a finding that is a real violation.
- **Conventional commits.** Every commit message ends with:
  `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`
- **THE WITHHOLDING RULE.** Several tasks below specify *what a page must contain and what it must satisfy*, and say nothing about how it should look. That is deliberate and it is the point of the project — see spec §2. If a task is silent on colour, spacing, type, layout or component structure, derive it from the Jig rules via `/jig`. Do not ask for a visual specification; you will be told to decide it yourself.

## Task 3: The rule parser

Pure TypeScript. Fully specified here, because getting it wrong silently omits rules.

**Files:**
- Create: `src/content/rules.ts`
- Test: `test/rules.test.ts`

**Interfaces:**
- Consumes: `.jig-corpus/rules/*.md`, `.jig-corpus/rules.index.json`
- Produces:
  ```ts
  export interface Entry {
    id: string;            // "A-01" | "P-02"
    kind: 'rule' | 'spec';
    section: string;       // "A"
    number: number;        // 1
    title: string;
    wrong?: string;        // rules only, ❌ line, no marker
    correction?: string;   // rules only, ✅ line, no marker
    notes: string[];       // prose after ✅ — the CLI drops this, we keep it
    body?: string;         // specs only, full body
    sourceFile: string;    // "00-anti-patterns.md"
    bucket?: 'mechanical' | 'hybrid' | 'judgment';
    severity?: 'error' | 'warning';
    detector?: string;
    since?: string;
  }
  export function loadEntries(pkgRoot: string): Entry[];
  ```

- [ ] **Step 1: Write the failing tests**

```ts
import { describe, it, expect } from 'vitest';
import { loadEntries } from '../src/content/rules.js';
import { fileURLToPath } from 'node:url';
import { join, dirname } from 'node:path';

// The corpus is fetched to .jig-corpus/ by scripts/fetch-corpus.mjs.
// jig-ui is deliberately NOT a dependency — see Global Constraints.
const corpus = join(dirname(fileURLToPath(import.meta.url)), '..', '.jig-corpus');
const entries = loadEntries(corpus);
const byId = (id: string) => entries.find((e) => e.id === id)!;

describe('rules parse from the published package', () => {
  it('finds both rules and specs', () => {
    expect(entries.filter((e) => e.kind === 'rule').length).toBeGreaterThan(100);
    expect(entries.filter((e) => e.kind === 'spec').length).toBeGreaterThan(10);
  });

  it('parses a rule into its wrong/correction pair', () => {
    const a02 = byId('A-02');
    expect(a02.title).toBe('Gradient text on headings');
    expect(a02.wrong).toContain('background-clip: text');
    expect(a02.correction).toContain('--color-text-strong');
    expect(a02.wrong!.startsWith('❌')).toBe(false); // marker stripped

    expect(byId('A-04').notes.length).toBeGreaterThan(0);
  });

  it('joins index metadata onto the rule', () => {
    const a02 = byId('A-02');
    expect(a02.bucket).toBe('mechanical');
    expect(a02.severity).toBe('error');
    expect(a02.detector).toBe('gradient-text');
  });

  it('does not mistake a spec subheading for a rule', () => {
    // 03-patterns.md has `### Three weights` inside P-02. It is not a rule.
    expect(entries.some((e) => e.title === 'Three weights')).toBe(false);
  });

  it('parses a spec with its body', () => {
    const p02 = byId('P-02');
    expect(p02.kind).toBe('spec');
    expect(p02.title).toBe('Button');
    expect(p02.body!.length).toBeGreaterThan(200);
```

- [ ] **Step 2: Run the tests to verify they fail**

Run: `npx vitest run test/rules.test.ts`
Expected: FAIL — `loadEntries` is not defined.

- [ ] **Step 3: Implement the parser**

Use these exact patterns, which are the ones the CLI uses:

```ts
const RULE_HEADING = /^###\s+([A-Z])-(\d+)\s+(.+?)\s*$/;
const SPEC_HEADING = /^##\s+([PM]-\d+)\s*(?:·\s*)?(.*?)\s*$/;
```

Rules: on a `RULE_HEADING`, start a new entry. The first line starting `❌` is
`wrong`, the first starting `✅` is `correction`; **every non-empty line after
the correction, until the next heading, is pushed to `notes`**. That last clause
is the superset — see `DRIFT.md` D-002.

Specs: on a `SPEC_HEADING`, collect lines until the next `##` that is not a spec
heading. Its `###` subheadings are part of the body, never rules.

Join `rules.index.json` by id. **Throw** on a rule with no index entry and on an
index entry with no rule. Never skip silently: a docs site that quietly omits a
rule is the same failure class as a check that goes quiet when its subject moves.

- [ ] **Step 4: Run the tests to verify they pass**

Run: `npx vitest run test/rules.test.ts`
Expected: PASS, all 7.
